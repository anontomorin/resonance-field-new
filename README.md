# 共振场：回声海图

> 一次关于海洋声景的互动探索：海洋并非无声。穿过未知与干扰，重新听见生命信号。

一款以"声波帮助玩家感知未知空间"为核心的纯前端 2D 网格探索益智游戏。
玩家扮演一次虚构的深海声景调查任务的操作员，身处一张大部分区域不可见的网格地图中，
通过移动与发射探测脉冲逐步显现通道、墙壁与观测节点，记录全部必需节点后开启出口并离开调查区。
主线关卡通关时会附上一张可追溯来源的「深海声景档案」知识卡。

- 技术栈：Vite + TypeScript + Canvas 2D + HTML/CSS（可选 Web Audio 程序音效）
- 平台：桌面与移动端现代浏览器，纯前端，无后端 / 账号 / 数据库 / 外部资源
- 声波模型：**双模型可切换** —— 八方向射线照度场（默认，有距离衰减）与四方向网格 BFS，
  两者共用同一份调度与评分实现，见下文「声波传播：双模型」
- 三种玩法：**主线关卡**（教学关 + 4 个经过验证的正式关卡）、**随机回声**（种子生成，
  无限关卡）、**我的关卡**（内置编辑器自制地图 + 分享码互相分享）
- 内置关卡：教学：初鸣 / 初次回响 / 隔墙之声 / 回声走廊 / 共振核心
- 陷阱与生命值：地图里散布**尖刺**（扣血）与**回声干扰器**（抹掉探索记忆），
  声波扫过的陷阱会被永久记住，力竭重开也不会忘记——见下文「陷阱与生命值」

## 主题与事实边界

作品以海洋声景为现实议题，但游戏机制与科研事实严格分开，避免过度表述：

- 海洋声景、生命信号与水下噪声相关表述，依据 NOAA / NOAA Fisheries / 国际海事组织（IMO）
  的公开资料；每张通关知识卡都带有机构名与外链来源（完整来源见下方「资料来源」）。
- 游戏中的脉冲、墙体遮挡与「回声干扰器」是**玩法抽象**，不等于真实声场或真实声呐模型；
  干扰器也不是真实船舶噪声的物理传播仿真。
- 通关按脉冲次数评星只是**游戏效率指标**，不代表现实环境噪声的减排量。
- 节点是游戏目标，不代表已识别的鲸、海豚或某个物种；随机关卡也不对应任何真实海域。
- 画面里缓慢漂移的微粒与上浮气泡是**氛围装饰**（均匀铺满画面、不携带任何地图信息），
  不是真实海况、悬浮物浓度或生物分布的再现。
- 作品只链接官方页面，不下载或嵌入未经确认授权的科研机构音频 / 图片。

## 术语表

游戏文案在涉及海洋声学时统一按下列口径用词，避免把游戏机制混同成科研事实：

| 术语 | 本作口径 |
|---|---|
| 海洋声景（ocean soundscape） | 某片海域在一定时间与条件下呈现的声音环境，可能同时包含生物、自然环境与人为活动产生的声音。 |
| 水下噪声（underwater noise） | 描述可能影响海洋动物或声学环境的声音；不简化成单纯「音量大」。 |
| 水下辐射噪声（underwater radiated noise, URN） | 船舶等声源向水中辐射的噪声；出现在面向普通玩家的卡片里时会附简短解释。 |
| 被动声学监测（passive acoustic monitoring） | 记录环境中**已有**的声音来开展监测；与玩家在游戏里**主动发射**脉冲探测是两回事。 |
| 探测脉冲 / 游戏脉冲 | 本作的玩法规则。作品**不实现**真实主动声呐的信号发射、回波测距与水下声场传播，因此不使用「主动声呐」这个词。 |
| 游戏化抽象 | 为玩法服务的简化规则：墙体阻断脉冲、固定格子衰减、干扰器清除记忆都是本作的游戏规则，不是对真实海洋声场的完整模拟。 |

## 安装与运行

```bash
npm install        # 安装依赖
npm run dev        # 启动开发服务器（默认 http://127.0.0.1:5173）
npm run build      # 类型检查 + 构建到 dist/
npm run preview    # 本地预览 dist 构建产物
npm run validate   # 运行算法 / 关卡 / 陷阱 / 随机关卡 / 分享码校验（Node 端，314 项检查）
```

`dist/` 使用相对路径（`base: './'`），可以直接作为静态站点部署到任意子路径
（GitHub Pages、对象存储、Nginx 子目录都无需改配置）。

> **跨平台说明**：esbuild 与 rollup 需要平台专属的二进制包。本项目把
> Windows 与 Linux 两套都写进了 `optionalDependencies`
> （`@esbuild/win32-x64` / `@rollup/rollup-win32-x64-msvc` /
> `@esbuild/linux-x64` / `@rollup/rollup-linux-x64-gnu`），
> 这样本地（Windows）与 CI（Linux）都能安装成功，`npm ci` 在两条平台上表现一致。
> 如果你在 macOS 上开发且报缺少平台包，按同样思路补一个 `@rollup/rollup-darwin-*` 即可。

仓库自带自动化 workflow（`.github/workflows/deploy.yml`）：推送到 `main` 即自动

### 首次设置（只需做一次）

打开 https://github.com/anontomorin/resonance-field/settings/pages ，
在 **Build and deployment → Source** 里选：

- **GitHub Actions** ← 推荐（workflow 会自动发布，无需手动操作）
- 或 **Deploy from a branch**，分支选 **`gh-pages`**、目录选 **`/ (root)`**

两种模式 workflow 都会正确处理：

| Source 模式 | 实际由谁发布 |
|---|---|
| GitHub Actions | `deploy` job（Pages Artifact） |
| Deploy from a branch → `gh-pages` | `peaceiris/actions-gh-pages` 把 `dist/` 推到 `gh-pages` 分支 |

> **⚠️ 千万不要把 Source 选成 `main` 分支 + `/ (root)`。**
> 那会让 Pages 去读仓库根目录的**源** `index.html`——它是 Vite 的模板，
> 里面**没有** `<script>` / `<link rel="stylesheet">`（这些标签是构建时才注入的）。
> 结果是一个"看起来加载成功、但没样式、没交互"的空壳页面。
> 本项目线上曾出现过这个现象，根因就是 Source 被设成了 `main` 根目录。

## 操作方式

| 操作 | 键盘 | 手柄 | 说明 |
|---|---|---|---|
| 移动 | `W A S D` / 方向键（可长按） | **十字键 / 左摇杆** | 逐格移动，不能穿墙 |
| 发射声波 | `Space` | **A / RT** | 从当前位置发射脉冲，冷却 0.6 秒 |
| 重开本关 | `R` | **Y** | 恢复本关初始状态 |
| 暂停 / 继续 | `Esc` | **Start** | 暂停时模拟完全冻结 |
| 声音开关 | 界面按钮 | — | 默认静音，程序合成音效，不依赖远程资源 |

移动端 / 触屏：窄窗口（宽 < 860px）或主指针为触摸（手机、平板）时自动显示
虚拟摇杆与声波按钮，键盘提示同步切换为触摸提示；窗口变宽（或旋转/缩放）
时会重新判定并自动切换。带触摸屏的笔记本（同时有鼠标）不会误显示摇杆。

### 手柄

接上手柄**无需任何设置**，边玩边插也认：HUD 底部的键位提示会自动从键盘换成手柄，
拔掉再换回来（触摸优先——摇杆已经占住屏幕底部时不再叠加手柄提示）。

- **游玩中**：十字键 / 左摇杆移动，`A` 发射声波，`Y` 重开，`Start` 暂停。
- **菜单中**：十字键 / 左摇杆**循环切换**选项，`A` 确认。焦点用 1px 琥珀描边标出，
  与键盘 `Tab` 的选中样式是同一套视觉。除编辑器（那是鼠标 / 触摸的作画界面）外，
  其余界面都能纯手柄走完；否则打完一关就会卡在结算面板上点不到"下一关"。

几处刻意的取舍：

- **摇杆取"位移较大的轴"**。摇杆给的是连续量，而游戏是四向网格，
  斜推不该变成"斜着走"。同时加 0.42 死区，廉价手柄的回中漂移不会让角色自己走。
- **重开放在 `Y` 而不是更顺手的 `B`**。`B` 紧挨 `A`，而重开不可逆（丢掉本局已探索
  的记忆），放到离拇指更远的 `Y` 上，误触代价小得多。
- **菜单导航是线性循环，不是空间寻路**。空间寻路要为每个界面单独处理布局
  （两列关卡网格、三页签、动态生成的结算按钮），规则又长又脆，还很难向玩家解释
  "为什么按左跳到了这里"；线性循环只看 DOM 顺序，永远可预测、可复现、可测试。
- **按钮不给 `disabled` 的卡片**（如未解锁关卡）会被导航自动跳过，焦点不会停在一个
  按了没反应的地方。

实现上用的是 Gamepad API 的**轮询**——这个 API 本来就没有 `keydown` 那样的按键事件，
只有"当下快照"，所以由主循环每帧读一次 `navigator.getGamepads()`。

按键映射**优先按 W3C 标准布局**（`mapping === 'standard'`）。蓝牙连接的国产手柄
经常拿不到这个标记，此时索引表并不适用，所以实现里准备了一张**兜底候选表**：
十字键同时试 `12~15` 与 `4~7`、A 键试 `0/1/2`、Start 试 `9/8/10`；
摇杆则扫描所有相邻轴对，取偏移最大的一对（不假定左摇杆一定在 `axes[0]/[1]`）。
取舍是"宁可偶尔少认一个键，也不能让整个手柄失效"。

**手柄连上了却怎么按都没反应？** 按以下顺序排查：

1. **先按一下手柄上的任意键**。Chrome 只在收到手柄输入后才把设备交给页面，
   这是浏览器安全策略，不是游戏的问题。
2. 确认页面上出现了手柄键位提示（`A 发波 / Y 重开 / Start 暂停 / 十字键移动`）。
   若仍显示键盘提示，说明浏览器还没把手柄交给页面，回到第 1 步。
3. 还不行的话，打开浏览器控制台执行
   `__resonance.getDebugSnapshot().gamepadDiag`，会输出手柄的原始上报值：
   `mapping` / `standard` / `buttonCount` / `axisCount` / `pressedIndices` / `axes`。
   对着这些值就能判断是**映射非标准**（`standard: false`）、
   **轴序不同**（推摇杆时 `axes` 里动的不是第 0/1 位）、
   还是**按键只更新 value 不更新 pressed**（`pressedIndices` 一直为空）。

## 玩法规则

1. 地图初始几乎完全未知，只有玩家脚下 1 格可见。
2. 第一次游玩从**教学关「教学：初鸣」**开始：按提示逐步完成移动 → 发射声波 →
   激活节点 → 进入出口，其余关卡依次解锁。
3. 每次脉冲按默认的**八方向照度场**（`model: 'field'`）逐格步进：
   - 能量随距离衰减，有效感知半径约 5 格（`fieldFalloff ^ n >= fieldThreshold`），**越远越暗**；
   - 射线撞墙时注入半格残留能量后终止，所以**声波不能穿墙**，墙只以"边界"形式显现；
   - 被照亮的格子按传播距离逐步显现（`stepDelay = 0.055 秒 / 格`），
     显现持续 2.2 秒后回落为约 20% 亮度的探索记忆。
   （模型可切换为四方向 BFS，见「声波传播：双模型」；两者共用同一套调度、可见性与评分口径。）
4. 共振节点（暖黄色）只有被脉冲**实际抵达**时才会激活，且永久保持。
5. 全部必需节点激活后出口开启；走进出口即通关。**出口格本身一直是可以走上去的**
   （未开启时踩上去只是"先来看看"，会提示还不能离开，但不会结束本局）。
6. 通关后按**本局脉冲次数**给出 1~3 星评价（详见「星级评分」一节）。
7. 主线关卡进度（解锁 + 最佳用时 + 最佳星级 + 最佳脉冲次数）保存在 localStorage，
   刷新页面后保留；自制关卡保存在另一个键（`resonance-field:custom:v1`），两者互不干扰。

## 陷阱与生命值

在"看不见地图"的游戏里加陷阱，最容易掉进的坑是变成**纯运气**：
踩到之前完全无从预判，踩到之后立刻忘了在哪，于是每一步都是在赌。
所以这套机制的设计目标不是"惩罚玩家"，而是**让危险变成一种可管理的信息**。

**两种陷阱**

| 陷阱 | 字符 | 效果 | 设计意图 |
|---|---|---|---|
| 尖刺 | `^` | 扣 1 点生命，随后 1 秒无敌帧 | 直接压力，逼你把"已知危险"纳入路线规划 |
| 回声干扰器 | `*` | 以自身为中心、半径 4 格内清除探索记忆（一次性，不扣血） | 惩罚的是"记忆"这个核心资源，而不是血条 |

**关键的三条规则**

1. **陷阱会被永久记住。** 脉冲扫到陷阱后，那一格会留下红色警示标记，
   在 20% 亮度的普通地面记忆里依然醒目。没有这条，陷阱就只是运气；
   有了它，玩家才可能"看见 → 记住 → 绕开"。
2. **力竭重开保留陷阱记忆。** 死亡清空普通探索记忆，但已发现的陷阱标记留着
   （`rememberTrapsOnDeath: true`）。第二次尝试时你知道危险在哪，失败换来的是情报而非徒劳。
3. **干扰器是一次性的，也抹不掉陷阱标记。** 它的惩罚是"重新迷路"而不是"重新挨打"，
   踩过即失效，无法被反复刷取。

**为什么不回血**（`healOnResonator: 0`）：回血会把尖刺从"路线规划问题"降级成"资源消耗问题"，
玩家只需暴力推进。不回血让每一次踩中都必须被认真对待，也让"多拿一个节点"这种
看似安全的动作带有真实取舍。

**生命值是 3，还是 4？** 由分析器算出来决定，不是拍脑袋定的。
`minSpikeCostToClear()` 用 0-1 BFS + 位掩码 DP 求出"走遍所有节点再进出口"的**理论最少踩刺次数**：
- 若 `minSpikeCost >= maxHealth`，这一关理论上就打不过去，会被判为**不可玩并拦下**；
- 残局关卡「共振核心」的迷宫最窄处只有一格宽，尖刺必然落在必经之路上（最少踩 2 次），
  于是它单独把 `maxHealth` 覆盖为 4：保留"必须硬吃两次"的压迫感，又留出 2 点容错。

**随机地图的额外保险**（`RANDOM_SAFETY_MARGIN = 2`）：分析器算的是**最优路线**的代价，
而人会走得不那么完美。实测确实存在"最优代价 1、但按直觉走会连踩 3 次"的随机图——
理论上能过，实际像运气，正是要避免的失败模式。因此随机生成额外要求
`minSpikeCost <= maxHealth - 2`，不自洽就换派生种子重来。

**相关参数**（`src/game/HazardConfig.ts`，关卡可用 `LevelDefinition.hazard` 覆盖）：

```ts
maxHealth: 3               // 生命上限
spikeDamage: 1             // 尖刺伤害
invulnerableTime: 1        // 受伤后的无敌秒数（防止连踩瞬间暴毙）
jammerRadius: 4            // 回声干扰器清除记忆的半径
shakeDuration: 0.35        // 受伤屏幕震动时长
rememberTrapsOnDeath: true // 力竭重开是否保留陷阱记忆
healOnResonator: 0         // 每激活一个节点回复的生命（0 = 不回血）
```

生命耗尽即**力竭**：本局以失败结束，弹出结算面板（用时 / 踩刺次数），
可「保留陷阱记忆重开」或返回关卡中心。冷却、计时、输入全部冻结，与通关互斥。

## 星级评分

每关按**本局发射的脉冲次数**评 1~3 星，不看到达时间、也不看踩了几次刺。

**为什么只看脉冲次数**：这一作的核心资源就是"看得见多少"，脉冲是唯一的照明手段。
用得多说明你在摸黑乱撞，用得少说明你真的把回波记进了脑子里、规划过路线。
用时受地图长度影响，踩刺数受运气影响，只有脉冲次数直接对应"有没有在动脑"。

**三星线是理论下界 `par` 再放宽一次探路容错。** `mapAnalysis.minPulsesToClear()` 按游戏真实的
传播规则（复用 `propagate()`，不另写一份 BFS）算出覆盖全部节点所需的**最少脉冲数**：

| 星级 | 条件 | 含义 |
|---|---|---|
| ★★★ | `脉冲 <= par + 1` | 会规划，最多只多打一次探路 |
| ★★ | `脉冲 <= par × 2` | 合理水平：探索得多一些，但仍有章法 |
| ★ | 其余 | 通关了，但基本是一发一发试出来的 |

> **这条线试过三个版本，最后定在 `par + 1`。**
>
> 1. **最初 `par + 1`** —— 但当时 `par` 的口径是"节点 + 出口各算一次"，
>    而主线五关的 `par` 恰好等于"走到每个节点各发一次"的朴素打法
>    （L1~L4 = 2 次、L5 = 3 次），于是**任何正常通关都直接三星**，评分没有区分度。
> 2. **收紧成严格的 `par`** —— 又走到另一个极端：`par = 2` 意味着玩家
>    "照到节点与出口后各只发一次波，并且一次走对位置"，
>    而真人不知道最优发射点在哪，首通几乎必然只有 1~2 星。
> 3. **最终 `par + 1`** —— 既保留"你得真的规划过"这条底线，
>    又给一次探路的容错，因为 `par` 是在"每次发波都落在最优位置"的理想条件下算出来的。
>
> 另一个必须知道的坑：`par` 里的"+1"有真实来源——**出口必须先被脉冲照亮才会画出来**
> （渲染层按 `visibility.alphaFor(exit)` 决定），玩家在照到出口前不知道它在哪。
> 第一版校验脚本按完美寻路直接走进出口，等于开了全图挂，测出的脉冲数低于 `par`，
> 让"三星有真实代价"这条断言假性失败。脚本现在会先补一发波照亮出口再走过去。

**重玩动力是刷新最佳脉冲次数**：每关会记录历史最佳星级与对应的脉冲次数
（存档键 `resonance-field:progress:v2` 的 `bestStars` / `bestPulses`），
星级是它的粗略档位，具体数字才是要刷的目标。更差的成绩不会覆盖最佳记录。

**相关参数**（`src/game/StarRating.ts`）：

```ts
thresholdsFor(par) → { three: par + 1, two: max(par + 2, par * 2) }
```

| 关卡 | par（照度场） | 三星线 | 二星线 |
|---|---|---|---|
| 教学：初鸣 | 2 | 3 | 4 |
| 初次回响 | 2 | 3 | 4 |
| 隔墙之声 | 2 | 3 | 4 |
| 回声走廊 | 3 | 4 | 6 |
| 共振核心 | 4 | 5 | 8 |

> 上表是**照度场模型**（当前默认）下的理论下界。改回 `bfs` 模型时 `par` 会是
> `2/2/2/2/3`——两种模型的感知半径不同（照度场约 5 格、BFS 8 格），
> `par` 与星级阈值跟着模型走，这也是把模型做成开关、并让评分复用同一份传播实现的原因。

随机关卡与自定义关卡用同一套标准，因此星级可以跨关卡横向比较。

## 三种玩法

### 主线关卡
教学关 + 4 张手工设计关卡，逐关解锁。通关面板提供「下一关 / 重玩 / 关卡列表」，
并展示本局星级、脉冲次数与理论最优值；关卡卡片上显示历史最佳星级。

### 随机回声
每次按种子生成一张全新迷宫，种子可手动输入、可复制、可分享：

- 四档预设：小（4×3 / 1 节点）、普通（7×5 / 2）、宽阔（10×7 / 3）、纵深（14×9 / 4）；
- 生成算法 = 递归回溯迷宫 → 编织（braid，按概率打通死胡同）→ 按 BFS 距离场布点；
- **生成后会自检**：用与编辑器完全相同的 `analyzeRows()` 判定可玩性，
  不通过就换派生种子（`seed + 尝试次数 × 7919`）重试，最多 12 次，仍失败则退回保底房间；
- 同一种子必然生成同一张图（内置 mulberry32 伪随机），因此种子就是关卡本身；
- 通关面板提供「换一张新的 / 再玩这张 / 返回随机设置」。

### 我的关卡（编辑器 + 分享码）
- 编辑器用 DOM 网格承载绘制（命中测试简单，移动端也能直接拖着画），
  支持画笔拖拽连续绘制、一键生成迷宫、清空为地面、补外边框、尺寸调整（保留已有内容）；
  调色板含墙 / 地面 / 出生点 / 节点 / 出口 / **尖刺** / **回声干扰器** 七种；
  一键生成走的是 `buildRandomMap()`（带"人类打得过"自检）而非裸的 `generateMapRows()`，
  所以生成出来的图不会自相矛盾地报"无法通关"；
- `S` 与 `E` 各只能有一个（放置时自动清除旧的）；
- 右侧实时显示校验结果，校验由 `analyzeRows()` 统一提供，
  保证**"编辑器说能玩"就一定能在游戏里跑通**；
  有错误时只列错误，仅有提醒时也会明确给出"校验通过（有提醒），可以试玩 / 分享"，
  避免陷阱提醒把正面信号挤掉；
- 可直接「试玩」，试玩结束能一键回到编辑器继续改；
- 保存到本地后可「导出分享码」，把地图发给朋友。

## 分享码

分享码是一串纯文本，不需要服务器，复制粘贴即可传递。对外是**可读化外形**
（`RESO·…` / `RESE·…`，全角中点分隔），内部载荷沿用紧凑的 `RFM1~…` / `RFR1~…`：

```text
自定义地图：RESO·<宽36进制>·<高36进制>·<行程编码地图>·<校验和>·<base64url 标题>   （内部 RFM1~…）
随机种子：  RESE·<种子>·<列>·<行>·<节点数>·<编织率×100>                            （内部 RFR1~…）
```

- 地图用 **RLE 行程编码**压缩（`g#1S4.1#` 这样的紧凑形式），一张 21×15 的迷宫约 40~60 字符，
  完整的自定义关卡分享码通常在 150~500 字符之间（弹窗会直接标出字符数，便于判断有没有被截断）；
- **FNV-1a 校验和**覆盖 `编码地图~宽~高~编码标题` 四段，粘贴缺字符或错字符会被拒绝并提示；
- 解析时自动容忍首尾空白与换行（从聊天软件里复制很容易带上），前缀 `reso`/`rese` 大小写也认；
- 标题用 base64url 编码，支持中文与 emoji；
- **旧的 `RFM1~…` 格式继续可解析**，已经发出去的老分享码不会失效。

### 关于「加密」：这里刻意没做

用户提过"分享码能否加密一下，看起来更美观"。结论是**只做可读化外形，不做加密**，
理由是加密在这套约束下换不到任何东西：

- 这是**纯前端、无服务器**的游戏，地图就在玩家自己的浏览器里。加密必然要把密钥一起发出去，
  拿到码的人（以及任何改代码的人）都能解出来 —— 没有真实的机密性可言；
- 代码是**全开源**的，算法和密钥都写在 `shareCode.ts` 里，等于公开；
- 而代价是实打实的：码变长（长地图本来就 200+ 字符）、出错时更难排查（用户没法自查那串是不是被改坏）、
  也挡住了"纯文本可直接粘贴"这个核心便利。

真正让人**误以为在加密**的写法（固定密钥异或、凯撒位移、把 base64 当密码学）最糟 ——
它给了一种虚假的安全感，读代码的人还得先花时间确认"这到底保护了什么"。
所以这里的目标是**可读、好看、一眼看出是"一张迷宫图"**，而不是**看不懂**。

> 如果哪天真需要"只让指定的人打开"，那需要的是**服务端签发 + 有效期**，
> 属于产品机制变化（要后端），不是给这串字符串套一层加密能解决的。

### 九宫格边框的两个坑

`frame-panel.png` 用作 `border-image`，实现方式是
**绝对定位的 `::before` + `inset` 与 `border` 同宽**，因此边框层不参与布局、不会挤掉内边距。

1. **切片必须覆盖整条不透明边框带。** 原图 768px 里，金属带 + 黑色密封圈 + 青色内线
   一共占到约 135px；起初按 72 切片，等于把密封圈和青线切进了中心切片。
2. **不能加 `fill`。** 加了 `fill` 之后中心切片会被拉伸铺满整个面板内部，
   上面那条黑色密封圈就变成一层盖住正文的幕布——表现是"文字被裁掉一半"，
   但 DOM 检查完全正常，很容易误判成排版问题。

正确写法（`src/styles/main.css`）：

```css
.panel::before,
.shell::before {
  content: '';
  position: absolute;
  inset: -28px;
  border: 28px solid transparent;
  border-image: url('../assets/art/frame-panel.png') 150 stretch; /* 无 fill */
  pointer-events: none;
  z-index: 2;
}
```

### 颜色与语义

只有三档底色：海沟 `--hull-900 … --hull-600`、玻璃 `rgba(8,19,27,.72)`、读数 `--ink`。

语义色纪律不变：**青 = 正在发生的能量**（声波、玩家、已探索地板、可交互焦点），
**琥珀 = 强调与来源标记**，**薄荷 = 通过 / 已归档**，
**危险色只给尖刺与干扰器**。语义色不拿来当装饰。

### 画布与界面的分工

画布保持上一版已经修正过的两条底线：

- **墙必须显著暗于地面**（`wallFill` 近黑 vs `floorFill` 中灰），这是功能性对比，不是审美问题；
- 声波是玩家获取信息的唯一手段，主波前的 `alpha` 保持 `1.0`、线宽 `2.5`，
  不跟着界面一起"压暗"。

新增的海洋氛围元素（缓慢漂移的微粒、上浮气泡）**均匀铺满画面、低透明度、
不携带任何地图信息**，因此不会和"亮起来的部分才是信息"这条规则冲突。

远景海沟（`BackgroundRenderer`）用 **cover 等比铺满**而不是拉伸：
竖屏画布又高又窄，直接拉伸会把海沟拉成一缕缕竖条；cover 只做裁切，
再叠上缓慢的推拉、体积光与焦散。系统偏好减少动态效果时，这些运动全部停在静态构图。

地图不再按整块画布居中，而是**居中在 HUD 顶栏与底栏之间的观察窗里**：
`CanvasRenderer.refreshInsets()` 每 400ms 量一次 `.hud-top` / `.tipbar` / `.hud-bottom`，
把地图压进真正空出来的区域。这样教程提示条和移动端摇杆都不会再压住地图中央。

### 首页的信息层级

首页在标题下方放了一条**三步循环条**（进入未知海域 → 发射探测脉冲 → 完成观测记录）。
在此之前，玩家必须点进教学关才知道"脉冲会被墙挡住、节点要激活、出口会开"，
而这三件事恰好是这个游戏与普通迷宫游戏的全部区别。

右舷是一整块舷窗：压环是 AI 生成的金属环，环内是玻璃底纹 + 扫描扇形 + 同心刻度环。
整块舷窗是 `aria-hidden` 的纯装饰，**不进入手柄的线性焦点序列**；
真正承载信息的是它下方三行读数（探测半径 8 格 / 墙体遮挡 生效 / 回声干扰 存在），
而且只写游戏里真实存在的机制。

### 装饰层纪律

- 所有装饰都是伪元素或 `aria-hidden` 元素，`pointer-events: none`；
- **不改动任何 `requireEl` 依赖的 DOM id**；
- 所有装饰动画都在 `@media (prefers-reduced-motion: reduce)` 里关闭；
- 结算面板不拦截手柄的线性焦点导航。

### 窄屏取舍

窄屏（≤860px）上三步循环条**竖排**而不是横滑：横滑会把第 3 步截断成半个词，
读者会误以为那就是文案结尾，比直接不给更糟。

手机上标题必须先进首屏，所以舷窗缩到 196px 并让位到标题之后；
触摸设备底部有摇杆与声波键，HUD 读数带整体抬高 `190px`，不会被压在摇杆下面。

## 技术实现

### 声波传播：双模型（src/sonar/Propagation.ts）

脉冲不是"画一个圆把圆内格子点亮"，而是两种可切换的真实传播模型，
由 `SonarConfig.model` 选择。保留两套实现是为了能用同一组校验做 A/B 对比，
而不是拍脑袋换一套手感。

**`bfs`（原模型）—— 四方向网格最短路径：**

- 起点为玩家当前格，距离 0；
- 只沿上 / 下 / 左 / 右四个方向扩展，只把可通行格入队；
- 遇到墙格：记入"边界墙显现集合"，不入队，因此墙后区域不会泄露；
- 输出整数步数，任意一圈上的格子**等亮**（没有远近明暗）。

**`field`（当前默认）—— 八方向射线照度场：**

- 从起点向 8 个方向（4 正交 + 4 对角）各投一条射线，用
  **DDA / Amanatides–Woo 步进**逐格推进（不是固定步长采样，见下）；
- 每进入一个新格乘以衰减系数 `fieldFalloff`，因此输出的是 **0~1 的连续能量**，
  表现为"越远越模糊"；
- 撞墙时给墙格注入半格残留照度（"声波打在这面墙上"），射线立即终止；
- 由于是连续值，"算不算看见"从布尔判断改成了阈值判断，
  阈值 `fieldThreshold` 属于**玩法参数**，放在 `SonarConfig` 而不是传播函数里。

| | bfs | field |
|---|---|---|
| 方向 | 4 | 8（含对角） |
| 输出 | 整数步数 | 0~1 照度 |
| 有效感知半径 | 8 格 | **约 5 格**（`0.86^n >= 0.3`） |
| 墙体显影 | 距离场 | 撞墙残留能量的 50% |
| 视觉 | 等亮圆环 | 中心亮、边缘暗的渐变 |

> **为什么必须是 DDA，而不是"每次前进半格再取 floor"。**
> 最初照度场按固定半步长实现，看似能防穿墙，实际在 45° 方向上是错的：
> 起点取格心偏移 `(x+0.5, y+0.5)` 后，对角方向的位置序列是
> `(x±0.5, y±0.5) → (x+1, y+1) → …`——每两步精确落在**整数格点**上，
> `Math.floor(2.0)` 只判给 `(2,2)`，于是 `(2,1)`、`(1,2)` 这两格**从未被采样**，
> 声波从两堵墙的夹角里穿了过去。DDA 用"到下一格线的距离"推进，
> 每步必进一格且落在格内，从根本上消除盲区。
> 校验脚本里有一个专门摆成夹角形状的回归用例守着这一点。
>
> 另外，DDA 每轮恰好跨一格，所以 8 个方向共用同一个每格衰减系数；
> 若给对角额外乘一次 `falloff`（早期版本的写法），会得到"同一圈上正交亮、对角暗"
> 的八角星，而不是物理上正确的等能圆。

**相关参数**（`src/sonar/SonarConfig.ts`，关卡可用 `LevelDefinition.sonar` 覆盖）：

```ts
model: 'field'        // 传播模型：'bfs' | 'field'
maxRange: 8           // 单次脉冲的最大传播格数
fieldFalloff: 0.86    // 照度场：每前进一格的能量衰减系数
fieldThreshold: 0.3   // 照度场：低于此值视为"看不见"
stepDelay: 0.055      // 每传播一格的动画间隔（秒）
revealDuration: 2.2   // 明亮显现持续时间（秒）
memoryAlpha: 0.2      // 探索记忆的透明度
cooldown: 0.6         // 发射冷却（秒）
revealPlayerTile: true // 踏入新格时是否点亮脚下
```

### 脉冲调度（src/sonar/PulseSystem.ts）

无论用哪个模型，传播结果都会被展开为**按时间排序的到达事件**
（`到达时间 = 格距 × stepDelay`），由主循环逐帧触发：
地图显影、节点激活都绑定在这些事件上。

这一层刻意**不感知传播模型**——它只消费"哪些格子在什么时刻被点亮、亮到什么程度"这张表。
所以换声波模型（bfs ↔ field）在这里的改动量是零，
唯一的差别是事件里多带了一个 `intensity` 字段（`bfs` 下恒为 1）。

同一时刻最多一枚活动脉冲；重开 / 切关 / 返回标题会 `cancel()` 清理脉冲与冷却，
杜绝旧回调污染新关卡。

### 可见性（src/sonar/VisibilitySystem.ts）

每格维护 `explored / brightUntil / lastRevealAt`，输出 0~1 的显现强度：
未知（0，不绘制任何布局）→ 当前显现（明亮 + 描边闪烁）→ 探索记忆（0.2 亮度）。

`field` 模型下这里还多记一列 `lastIntensity`（每格最近一次被照亮的能量），
供渲染层做"越远越暗"。注意它只负责**记录**、不做阈值判断——
"算不算看见"已经在调度层按 `fieldThreshold` 决定过了，
到这一层的都是已判定为可见的格子。同一格被反复照亮时取**最亮的一次**，
这样远处补一枪不会把近处的清晰度冲淡。

渲染层的叠加方式是 `memoryAlpha + (alpha - memoryAlpha) × intensity`：
照度只影响"当前明亮显现"这一段的高光强度，并以记忆透明度为下限，
保证已经探索过的地形即使照度很低也不会暗到认不出来。
`bfs` 模型下 `intensity` 恒为 1，结果与改造前逐像素一致。

另有一层**独立的 `knownTraps` 标记**：普通地面回落到 20% 亮度后几十格混在一起根本记不住，
而陷阱必须能被记住，否则在看不见的地图里踩陷阱就是纯运气。
所以只要声波扫到过（或玩家踩到过），陷阱就永久保留警示标记，
`forget()`（干扰器用）**只清普通记忆、绝不清陷阱标记**，
`reset(keepTrapMemory)` 则决定力竭重开时这层标记是否保留。
节点与出口的绘制对照度只做**半程**衰减：它们是硬目标，
再远也要能看出"那里有个东西"，否则玩家会以为声波没扫到而重复发射。

### 关卡与状态机

- 地图用等宽字符串数组描述（`#` 墙 / `.` 地面 / `S` 出生点 / `R` 节点 / `E` 出口 /
  `^` 尖刺 / `*` 回声干扰器），`TileMap.fromStrings` 在装载时校验行宽、字符合法性与 S/E/R 数量；
- 陷阱是可通行的（`isPassableKind` 只把 `wall` 排除），所以陷阱**不改变关卡可达性**，
  "节点能不能走到"的判定无需为陷阱调整；陷阱带来的风险由分析器单独用代价模型评估；
- 应用状态：`home → levelCenter → playing ⇄ paused → levelComplete → gameComplete`，
  另有一条 `home → editor → playing`（编辑器试玩）分支；
  通关后的按钮按关卡来源动态生成：主线给「下一关」，随机关给「换一张新的」，
  自定义关给「回到编辑器」；
- 键盘监听全局只注册一次（`InputController`），切换界面不会重复绑定。

### 随机关卡生成（src/gen/）

- `Rng.ts`：mulberry32 伪随机数发生器，同一种子必然产出同一序列，是整个随机系统的基石；
- `randomParams.ts`：四档预设 + 参数钳制（`clampParams` 保证越界参数不会崩）；
- `LevelGenerator.ts`：递归回溯迷宫 → 编织 → 按 BFS 距离场放置 S / R / E →
  调用 `analyzeRows()` 自检，不通过则换派生种子重试。

### 地图分析与分享码（src/levels/）

- `mapAnalysis.ts`：**编辑器实时校验、随机生成自检、导入校验、开发期校验脚本共用这一份实现**。
  除了常规的宽高 / 字符 / S/E/R 数量检查，关键的一条是
  **把出口 E 当作墙再做一次 BFS** —— 出口格在节点集齐前虽然**可以走上去**（改版后不再挡路，
  上去只是"先来看看"），但这条检查作为比玩法更严的一道保守防线保留下来：
  它禁止"有节点只能穿过出口才能到达"的布局，也就是不允许出口格成为地图上某条唯一通路上的必经点。
  这类地图会被判为不可玩；
  此外还用 `minSpikeCostToClear()`（0-1 BFS + 位掩码 DP）算出走完全程的**最少踩刺次数**，
  超过生命上限就判为不可玩，从根上杜绝"陷阱堆到打不过去"的关卡；
  `optimalVisitOrder()` 用同一份 DP 还原最优节点顺序，供校验脚本真实模拟通关；
  `minPulsesToClear()` 算星级下界 `par` 时，**必须复用当前生效的传播模型与参数**
  （它接收整个 `SonarConfig` 而不只是 `maxRange`）——否则评分会用旧模型、游戏跑新模型，
  两者悄悄不一致；
- `shareCode.ts`：RLE 压缩 + FNV-1a 校验 + base64url 标题的编解码，纯字符串、无依赖。
  陷阱字符刻意选 `^` 与 `*`：它们既不在小写 36 进制计数范围内、也不等于字段分隔符 `~`，
  因此 RLE 解析不会有歧义；校验和覆盖 `编码地图~宽~高~编码标题` 四段，改标题也会被发现。

### 移动端触摸控制与教学关

- `src/ui/TouchControls.ts`：基于 Pointer Events 的虚拟摇杆 + 声波按钮，
  只输出"方向 / 发射请求"两种输入，节流与判定仍由 `LevelSession` 统一处理；
  摇杆有 14px 死区并量化为四方向；
- 设备判定（`applyDeviceMode`）：主指针为粗指针（手机/平板）、或"只有触摸没有
  精确指针"、或视口宽 < 860px 时启用；resize / orientationchange 时重新判定，
  触屏笔记本（有鼠标）不会误显示摇杆；
- `src/game/TutorialGuide.ts`：教学关分步引导，每条提示绑定一个真实游戏事件
  （移动 / 发射 / 激活节点 / 出口开启），只有玩家真正完成该操作才推进到下一条；
- 教学关加入后关卡 id 顺延，存档键升级为 `resonance-field:progress:v2`。

### 手柄输入（`src/core/GamepadController.ts` + `src/ui/MenuNavigator.ts`）

- **轮询而非事件**：Gamepad API 不提供按键事件，只提供"当下快照"，
  所以由 `GameApp.update()` 每帧调一次 `poll()`。这也意味着手柄状态天然跟着主循环走，
  暂停 / 结算时不会偷偷累积输入。
- **与键盘共用动作集**：手柄把按键折算成同一套 `GameAction`
  （`src/core/InputController.ts` 里的类型），于是 `GameApp` 里两套输入走同一条
  优先级链（触摸 > 手柄 > 键盘），不需要为手柄分叉一份玩法逻辑。
- **边沿检测**：`poll()` 与上一帧的按住集合作差，只有"这一帧才按下去"才算一次按下。
  否则按住不放会在每帧触发一次声波 / 重开。
- **`reset()` 刻意不清"按住"状态**：玩家通常是按着 `A` 确认"下一关"，
  如果连按住状态一起忘掉，新关卡的第一帧就会再发一次声波。
- **映射分两条路**：`mapping === 'standard'` 时按 W3C 索引表读；
  否则走 `FALLBACK_BUTTON` 候选表（十字键试 `12~15` 和 `4~7`、A 试 `0/1/2`），
  摇杆用 `readStick` 扫描所有相邻轴对取偏移最大的一对。
  这是"连上了却按不动"的修复（见 `docs/测试报告.md` 缺陷 29）。
- **连接提示会记账**：在标题页插手柄时 HUD 不可见，
  提示先存进 `pendingPadToast`，等 `setState('playing')` 时补发 ——
  早先的实现直接丢弃，玩家得不到任何反馈，会误判成"手柄没被认到"。
- **可注入快照源**（`setSnapshotProvider`）：自动化验收里注入假手柄，
  覆盖的仍是 `navigator.getGamepads()` 这条真实路径，否则手柄逻辑只能靠插真机去测，
  回归时无法复现。
- **`diagnostics()` 暴露原始上报值**（`mapping` / `standard` / `axes` /
  `pressedIndices` 等），经 `getDebugSnapshot().gamepadDiag` 可取。
  手柄问题原本只能靠"按了没反应"描述，而这可能是映射、轴序、pressed 三种原因，
  有了原始值才能一次定位。
- **菜单导航**（`MenuNavigator`）按 DOM 顺序循环焦点，元素可见性用
  `getClientRects()` 判断而不是 `offsetParent`（覆盖层是 fixed 定位，后者不可靠）。
  隐藏页签里的按钮会因此被自动排除，焦点不会被送进看不见的地方。

## 已知限制

- 不做：真实声学仿真、3D、倒计时、在线排行榜（分享靠分享码字符串，无后端）。
- 声波模型是**离散网格上的近似**：`field` 模型用 8 条射线采样能量，
  而不是解波动方程；它能表达距离衰减与遮挡，但没有衍射、反射、干涉等真实声学现象。
  射线只到 8 个方向，斜向精度以 45° 为最小角分辨率。
- `field` 模型的有效感知半径（约 5 格）明显短于 `bfs`（8 格），
  这是 `fieldFalloff` 与 `fieldThreshold` 共同决定的，两个参数都可在 `SonarConfig` 中调整；
  改这两个值会同时改变手感与星级下界 `par`。
- 没有回血机制（`healOnResonator = 0`），这是刻意的设计选择而非缺失，理由见上文。
- 回声干扰器只清"探索记忆"，不影响陷阱标记；因此它更偏解谜压力而非生存压力。
- 声音默认关闭；浏览器未授权 AudioContext 时游戏照常运行。
- 自定义关卡只保存在当前浏览器；换设备 / 清缓存前请先导出分享码。
- 手柄适配**优先按 W3C 标准布局（`mapping === 'standard'`）映射按键**。
  Xbox / PlayStation / Switch Pro 等主流手柄都走标准布局；
  非标准布局（蓝牙国产手柄常见）会改用**兜底候选表 + 摇杆全轴扫描**，
  但兜底是**经验猜测**，不保证每个键都对得上 —— 极端布局的手柄仍可能有键位不符，
  可在控制台用 `__resonance.getDebugSnapshot().gamepadDiag` 看原始上报值定位。
  （浏览器也只会在用户动手柄之后才把它交给页面，这是 Chrome 的安全策略，不是这里的选择。）
- 手柄的自动化验收是**注入假手柄**跑通逻辑接线（见 `docs/测试报告.md`），
  覆盖了标准映射与三种典型非标准形态；实体手柄的按键手感、摇杆回中漂移、
  各厂商差异无法在无设备环境下覆盖，需人工确认。
- 分享码**只做可读化，不做加密**，长地图的分享码会较长（这是刻意换取"纯文本可直接粘贴"，
  以及"用户自己也能看懂那串有没有被截断"）；理由见上文「关于『加密』」小节。
- "玩家脚下 1 格"在踏入时可见（`revealPlayerTile`，可在配置中关闭），
  这是为了避免玩家在完全未知区域操作时完全失去自身位置参考。
